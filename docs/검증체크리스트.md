# 검증 체크리스트

코드(`index.html`)나 스키마를 고친 뒤 **배포 전에** 확인할 항목입니다. 자동 테스트가 없는 단일 파일 앱이라, 수정 때마다 *회귀(기존 기능이 망가지는 것)*를 사람이 잡아야 합니다. 이 목록은 실제로 버그를 잡아낸 확인들입니다.

## 0. 공통 준비

```bash
node serve.js        # http://localhost:4500 (이 컴퓨터 전용)
```
- 문법 확인(배포 전 필수): `index.html` 의 인라인 `<script>` 를 `new Function(...)` 으로 파싱해 오류가 없는지 본다.
- 브라우저 개발자도구 **콘솔 에러 0건** 확인(광고차단 확장이 내는 `ERR_BLOCKED_BY_CLIENT` 는 앱과 무관).
- **로컬에서 결과 화면을 눈으로 확인할 때**: 15초 자동 새로고침과 DB 재조회가 테스트 데이터를 *실제 DB 데이터로 덮어씁니다*. 목(mock) 데이터로 볼 때는 타이머를 끄고(`clearInterval(timer)`) `sb = null` 로 재조회를 막은 뒤 렌더하세요. 한참 뒤 스크린샷이 엉뚱한 데이터로 나오는 원인이 이것입니다.
- **라이브 DB 에 테스트 응답을 남기지 마세요.** 저장 경로는 `sb` 를 가짜 객체로 바꿔 *전송 페이로드만 가로채서* 검증하고, 실제 제출 테스트가 꼭 필요하면 별도 테스트 회차에서 한 뒤 `supabase/maintenance.sql` ④로 정리합니다. (브라우저 자동화로 화면을 클릭하다 *의도치 않게 진짜 제출*되는 일이 실제로 있었습니다.)

## 2. 구형(5축) 회귀 — 가장 자주 깨지는 곳

`group` 필드가 없는 예전 회차(축 5개, `key:"taste"` 1개)가 **예전과 똑같이** 나와야 합니다.
- 맛 = `taste` 1개 값, 관능 = 나머지 4개 평균, 히트맵 15칸(5축×3연령), 레이더 5각형
- 캡션이 `맛 … 관능(그 외 4축 평균)` 으로 표시(8축이면 `맛(3축 평균) … 관능(그 외 5축 평균)`)

## 3. 8축

- 맛(첫맛·뒷맛·간의 적절성 평균), 관능(나머지 5개 평균) 수치가 손계산과 일치
- 히트맵 24칸, 레이더 8각형, 항목별 막대 8줄
- 모바일 폭(375px)에서 **8개 옵션 선택 문항**이 여러 줄로 줄바꿈되고 한 글자씩 세로로 쪼개지지 않음

## 4. 항목 이름 편집

| 확인 | 기대 |
|---|---|
| 응답 0건 회차 | 이름·설명 수정 가능, 입력 즉시 미리보기 반영 |
| 응답 1건 이상 회차 | 입력란·되돌리기 버튼 **비활성** + "🔒 이미 N명이 응답" 안내 |
| 응답 수를 못 구함 | 안전하게 **잠금** |
| 9자 이상 / 이름 중복 | 저장 시도 자체가 차단(경고) |
| 빈칸 | 기본 이름으로 저장 |
| 저장된 설정 | `key`·`group`·제품·문항은 **그대로**, `label`·`hint`만 변경 |
| **최악 조건**: 이름 8개 전부 8자 | 레이더 라벨이 SVG 밖으로 안 잘림, 히트맵 헤더가 넘치지 않음 |
| 이름 바꾼 회차를 *비활성 상태로* 열람 | 히트맵·레이더·막대·엑셀(원자료·세그먼트)·PDF 전부 새 이름, 맛/관능 수치는 이름과 무관 |

## 5. 과거 회차 열람 (실제로 사고가 났던 곳)

활성 회차와 **축 구성이 다른** 과거 회차를 열어 본다(예: 활성이 8축, 과거가 5축).
- 과거 회차의 **원래 점수·항목 이름·문항**으로 그려져야 함(맛 0.0 으로 나오면 실패)
- PDF·엑셀도 같음
- 열람 뒤에도 전역 설정(`CFG`·`AXES`)이 **활성 회차로 복원**돼 있어야 함 — 안 그러면 응답 폼이 과거 회차 슬러그로 제출됨
- 회차를 빠르게 연속 전환해도 최종 화면이 마지막 선택과 일치(늦게 도착한 응답이 덮어쓰지 않음)

## 6. 투표 회차

- 제품 0개: 랭킹·히트맵·레이더 카드가 **아예 없음**, 문항별 득표·지지율·자유 의견만
- 동점이면 동점 항목을 모두 표시
- 응답자 정보를 끈 회차: 성별·연령 열이 엑셀에 없음

## 7. 응답 수집 (종단간)

가능하면 본인 Supabase 테스트 프로젝트에서:
1. 새 회차 저장(활성화는 하지 말 것) → 그 설정으로 응답 폼 렌더 → 실제 제출
2. REST 로 `svy_responses` 를 조회해 **8개 축 값이 정확한 key 로 저장**됐는지 확인
3. 결과 화면·PDF·엑셀에 그 응답이 같은 값으로 반영되는지 확인
4. 테스트 회차 숨김 → 응답·회차는 SQL 로 정리

## 7-2. 응답 폼 순서 지정(편집기)

| 확인 | 기대 |
|---|---|
| ▲▼ 로 제품·문항 이동 | 번호가 바뀌고 오른쪽 미리보기(Q 번호)가 같은 순서, 맨 위 ▲·맨 아래 ▼ 비활성 |
| 이름·선택지·사진 항목을 입력한 뒤 이동 | 입력값 유지 |
| 저장된 `blocks` 순서 | 편집기 순서와 동일 |
| 섞인 순서(제품·제품·투표·제품·의견)로 응답 폼 제출 | 누락 안내가 화면 순서대로, `items`/`extras` 정상 |
| 같은 이름 제품 / 브랜드 없는 제품 저장 | 저장 차단 + 안내 |
| **기존 회차를 편집기에 열었다가 저장 없이 닫기 → 같은 설정으로 다시 만들어 비교** | `blocks` 순서·옵션이 원본과 동일(회귀 없음) |

## 7-3. 브랜드별 PDF · 브랜드별 항목 이름

| 확인 | 기대 |
|---|---|
| 브랜드 2개 이상 회차의 PDF | 범위 선택이 보이고 `전체`에서 브랜드마다 새 페이지 |
| 범위를 브랜드 하나로 | 그 브랜드 제품만, 제목·파일명에 브랜드명, 다른 브랜드·투표 문항 없음 |
| `투표·의견만` | 투표 집계·응답자 구성·의견만 |
| 브랜드 1개 / 투표 전용 회차 | 범위 선택 없이 예전처럼 한 덩어리 |
| 브랜드별 이름 지정 → 응답 폼 | 해당 브랜드 제품에서만 바뀐 이름, 누락 안내 문구도 그 이름 |
| 같은 지정 → 제품 상세·히트맵·엑셀 원자료·세그먼트·CSV·PDF | 모두 브랜드별 이름, 이름이 다르면 히트맵·세그먼트가 브랜드별로 분리 |
| 맛·관능 수치와 판정 | 이름을 바꿔도 동일 |
| 공통과 같은 값으로 되돌림 / `공통 이름과 같게` | 저장된 설정에 덮어쓰기가 남지 않음(`meta.brandAxes` 없음) |
| 9자 이상·같은 브랜드 안 이름 중복 | 저장 차단 + 안내 |
| 기존 회차(5축·8축) 결과·PDF | 이전과 동일(덮어쓰기 없으면 완전히 같은 경로) |

## 7-6. 구분 제목 · 투표 집계

| 확인 | 기대 |
|---|---|
| 구분 제목이 섞인 폼 | 제목 띠가 보이고 문항 번호(Q)는 제목을 건너뛰고 이어짐, 필수 누락 안내는 질문만 대상 |
| 구분 제목 없는 기존 회차 | 이전과 동일(투표 집계는 한 묶음, 전체 폭 카드로 바뀜) |
| 결과 투표 집계 | 구분 제목별 묶음, 선택지마다 `N표 · P%`, 응답/무응답 인원, 동점 표시, 사진 투표 썸네일 유지 |
| 엑셀 `문항 집계` / PDF `투표·의견만` | 구분 제목 행(■)·띠가 문항 앞에 나옴, 원자료 열에는 구분 제목이 안 들어감 |
| 오래 캐시된 이전 버전 화면 | 구분 제목만 안 보일 뿐 폼은 정상 제출(알 수 없는 유형은 건너뜀) |

## 7-7. 소속 브랜드 · 1위 강조

| 확인 | 기대 |
|---|---|
| 구분 제목 소속 브랜드 지정 → 편집기 저장·재열기 | `brands` 가 보존됨(저장 설정과 편집기 왕복 값 동일), 소속이 없으면 필드 자체가 없음 |
| 결과 화면 브랜드 필터 | 다른 브랜드 소속 구분 제목·문항은 숨고, 소속 없는 공통 구역은 항상 보임. 해당 문항이 없으면 안내 문구 |
| 브랜드별 PDF | 그 브랜드 소속 + 공통 구역의 투표만 포함(다른 브랜드 소속 투표 없음), `전체`·`투표·의견만`에는 전부 |
| 1위 강조(pin) | 결과 맨 위 💡 줄과 PDF 맨 위·해당 브랜드 페이지에 `📌 … → 1위 (득표/응답 · %)`, 동점이면 표시, 브랜드 필터로 가려진 문항은 숨김 |
| 소속·pin 없는 기존 회차 | 이전과 동일(투표 집계 한 묶음, 💡 줄 변화 없음) |

## 7-8. 맛·관능 칸 수(회차·제품별)

| 확인 | 기대 |
|---|---|
| 설정 없는 회차(8축·5축) | 평균·판정·캡션이 이전과 **같은 수치**(제품별 값을 손계산과 대조), 편집기 저장↔재열기 전체 동일 |
| 제품 하나만 맛 4 | 그 제품 맛=앞 4칸 평균·관능=뒤 4칸 평균(손계산 일치), 다른 제품은 3/5 그대로 |
| 제품마다 구성이 다를 때 | 랭킹(화면·PDF)에 `맛N·관능M`, 판정 캡션 "맛(해당 항목 평균)", 엑셀 요약에 `맛/관능 칸 수` 열, PDF 항목 평균 표가 구성별로 분리, 제품 상세 그룹 헤더가 `맛 4항목`/`관능 4항목` |
| 회차 기본값을 바꿈 | 기본과 같아진 제품별 값은 저장에서 빠짐, 배지(맛/관능)가 즉시 바뀜 |
| 응답이 있는 회차 | 선택 상자 비활성, 저장 설정에 어떤 변경도 반영 안 됨 |

## 7-9. 편집 화면 분할 · 개별↔공통

| 확인 | 기대 |
|---|---|
| 넓은 화면(≥1020px)에서 편집기를 열기 | 왼쪽 편집기 + 오른쪽 폰 폭 미리보기, 아래로 스크롤해도 미리보기가 위쪽(top 64px)에 고정 |
| 좁은 화면(<1020px) | 미리보기가 편집기 위에 쌓임, 가로 스크롤 없음 |
| 카드 클릭/입력창 포커스 | 미리보기가 그 제품·문항(구분 제목 포함)으로 스크롤+강조. 폼에 안 그려지는 항목(이름 없는 제품)은 무시 |
| 제품에서 **이름만** 바꾸고 공통에서 그 칸 **설명**을 바꿈 | 제품에도 설명이 따라감(저장 설정에 이름만 있음) |
| 줄 ↺ / 제품 카드 ↺ 공통으로 / 일괄 통일 | 각각 해당 범위의 개별 설정만 제거(저장 설정에서 `productAxes`·`productTaste`·`brandAxes` 사라짐) |
| 기존 회차를 편집기에 열었다 저장해도 | **제품마다 실제 적용되는 이름·설명·맛/관능 그룹이 이전과 동일** |
| 응답이 있는 회차 | ↺ 버튼 계열 모두 막힘 |
| 편집 화면을 닫음 | 관리 화면 폭이 다시 좁아짐 |

## 7-10. 히트맵 제품별

| 확인 | 기대 |
|---|---|
| 기본(제품별) | 제품마다 제목 블록(제품명·브랜드·응답 수), 헤더는 그 제품 자신의 항목 이름 |
| 모든 칸 값 | 제출 데이터에서 직접 계산한 평균과 일치(제품×`전체`/연령대×항목) |
| 응답 없는 연령 | 해당 행 전체가 `–` |
| `통합` 토글 | 항목 이름 구성이 같은 제품끼리 합쳐 표시 |
| 브랜드·연령 필터 | 해당 브랜드 제품만 / 연령 한 줄만(`전체` 행 없음) |
| 엑셀 `세그먼트` | 제품마다 연령대·성별 블록, 값이 직접 계산과 일치 |
| 기존 회차(8축·5축) | 오류 없음, 제품 수만큼 블록 |

## 7-11. 투표 소속 규칙(바로 앞 제품 또는 구분 제목)

| 확인 | 기대 |
|---|---|
| 맨 앞 문항(제품·구분 제목 앞) | 공통 |
| 제품 → 문항 연속 | 그 제품의 브랜드(공통 메뉴면 여러 브랜드), 연속된 문항 모두 |
| 구분 제목(지정 없음) 바로 아래 | 공통 |
| 구분 제목(브랜드 지정) 바로 아래 | 지정한 브랜드 |
| 지정 있는 구분 제목 아래에 다른 브랜드 제품이 나온 뒤의 문항 | **그 제품**의 브랜드(가장 가까운 앞 블록이 우선) |
| 투표 표 | `응답 N명 기준` 표시, 득표수가 실제 응답 집계와 일치 |
| 화면 필터·엑셀 `소속` 열·PDF | 모두 같은 규칙 |
| 문항 `공통 질문으로 분리` 켬 | 앞 제품 소속과 상관없이 공통: 화면 필터(다른 브랜드 필터에도 보임)·엑셀 `소속`=공통·PDF 공통 투표 구역. 편집기 `결과 소속 →` 줄이 같은 결과. 끄면 원래 소속으로 복귀하고 저장 설정에 `common` 키가 남지 않음 |
| 편집기 `⧉ 복사` | 바로 아래에 복사, 문항은 새 ID·`(복사)` 문구, 제품은 `(복사)` 이름(겹치면 `(복사 2)`), 원본과 독립(복사본 수정이 원본에 영향 없음) |
| 자유 의견 `필수 응답` | 기본(키 없음)은 선택·기존 회차 동일. 켜면 `*` 표시·비우거나 공백만이면 제출 막고 안내+해당 문항으로 이동, 입력하면 통과, 진행 막대에 반영. 끄면 저장 설정에 `req` 키가 남지 않고, 저장 후 다시 열면 체크 상태 유지. 의견↔투표 유형을 바꾸면 필수 기본값(투표=필수, 의견=선택)으로 돌아감 |
| 자유 의견 `제목 띠` | 제목 띠(제목+작은 글씨 질문 문구) 바로 아래에 Q번호와 입력칸이 붙어 나오고, 번호는 질문 하나로만 올라감. 입력이 응답에 저장됨. 편집기 미리보기 위치 이동(카드 클릭)이 제목 띠로 정확히 감. 비우면 기존 모양 |
| 구분 제목 모양 | 제목 위에만 회색 띠가 있고 제목과 바로 아래 문항 사이에는 띠가 없어 아래 문항과 한 묶음으로 보임(밝은·어두운 화면, 미리보기 모두) |

## 7-12. PDF 실제 쪽 나눔(파일로 확인)

화면 미리보기에서는 쪽 나눔이 안 보이므로, **실제 PDF 파일**로 확인한다: `node tools/report-to-pdf.mjs out <회차ID> <사이트주소>` → 범위별 PDF 생성, `pdftotext -layout -f N -l N` 로 쪽별 내용 확인.

| 확인 | 기대 |
|---|---|
| 브랜드별 PDF(`○○만`) | 한 구역이 한 쪽(넘치면 표 단위로 자연스럽게 다음 쪽), 표·투표가 쪽 사이에서 갈라지지 않음 |
| 전체 PDF | 첫 쪽 요약 → 브랜드마다 새 쪽, **표 한두 줄만 담긴 쪽 없음** |
| 오른쪽 열(제공량 등)·마지막 선택지 | 잘리지 않고 모두 보임 |
| 단일 브랜드 회차 | 한 덩어리로 1쪽 안팎 |

## 7-13. 보고서 구성(메뉴 묶음)

`tools/report-to-pdf.mjs` 로 실제 PDF 를 만들고 쪽별로 확인한다(이미지로 보려면 PyMuPDF `get_pixmap`).

| 확인 | 기대 |
|---|---|
| `전체` | 요약(KPI·구성·판정 요약·📌·랭킹) 1번 → 공통 메뉴 구역 → ○○ 전용 구역 → 공통 질문 → 응답자 구성 → 의견 |
| 모든 제품 | 랭킹에 1번, 구역의 항목 평균 표에 1번(중복·누락 없음) |
| 모든 투표 | 전체 보고서에 정확히 1번(소속 구역 또는 공통 질문) |
| `○○ 관련` | 그 브랜드가 걸린 구역만(공통 + 자기 전용), KPI·랭킹·응답자 구성도 그 범위로 다시 계산, 의견 포함 |
| `투표·의견만` | 제품 표 없음, 투표를 구역별로 모아서 + 공통 질문 + 응답자 구성 + 의견 |
| 구역 1개(브랜드 1개·전부 공통) / 투표 전용 | 구역 구분·범위 선택 없이 한 덩어리 |
| 합성 구성(브랜드 3개·단독/공통 혼합·제품 없는 소속 투표) | 제품·투표가 빠지거나 두 번 나오지 않음 |
| 실제 PDF | 표·투표가 쪽 사이에서 갈라지지 않음, 표 한두 줄만 담긴 쪽 없음 |

## 8. 보안 (스키마를 건드렸을 때 필수)

```bash
# 익명 키로 삭제가 막혀 있어야 한다 (401 / permission denied 가 정상)
curl -s -X DELETE "$SUPABASE_URL/rest/v1/svy_surveys?slug=eq.__없는슬러그__" \
  -H "apikey: $ANON_KEY" -H "Authorization: Bearer $ANON_KEY"
curl -s -X DELETE "$SUPABASE_URL/rest/v1/svy_responses?survey_slug=eq.__없는슬러그__" \
  -H "apikey: $ANON_KEY" -H "Authorization: Bearer $ANON_KEY"
```
- 위 두 요청이 `42501 permission denied` 로 거절돼야 함. 거절되지 않으면 `supabase/schema.sql` 의 `revoke` 가 적용되지 않은 것.
- `supabase/schema.sql` 맨 아래 확인 쿼리가 `false / false / false / true`.
- 로컬 서버 폴더 이탈 차단: `curl --path-as-is "http://localhost:4500/..%2f<저장소 바깥 파일>"` → 403.

## 9. 배포 후

- 배포 확인: GitHub Pages 반영(보통 1~2분) 후 **캐시를 우회**해 확인(`Ctrl+Shift+R` 또는 주소 뒤에 `?v=아무값`). 사이트가 10분 캐시를 허용해 일반 새로고침은 옛 화면을 보여줄 수 있습니다.
- 응답 주소(`#admin` 없이)에서 **현재 활성 회차 폼**이 정상으로 뜨는지, **응답은 제출하지 말고** 닫기.
- 진행 중인 실제 회차의 설정·응답이 그대로인지 `svy_surveys` 를 조회해 `is_open` 과 응답 수 확인.
