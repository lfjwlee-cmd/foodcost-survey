# 보안 메모 — 무엇이 공개되고, 누가 무엇을 할 수 있나

한 줄 요약: **이 시스템은 "내부용 간이 도구" 수준의 보호**입니다. 아래 한계를 알고 쓰세요.

## 1. 저장소에 올라가도 되는 것 / 안 되는 것

| 항목 | 공개 저장소 | 이유 |
|---|---|---|
| `supabase/*.sql`(테이블 구조·보안정책) | ✅ 올려도 됨 | 구조일 뿐 데이터·키가 없음 |
| Supabase **anon / publishable 키** | ⚠️ 어차피 브라우저에 노출됨 | 응답자의 폰이 이 키로 DB에 접속하므로 페이지 소스에 보임. *공개돼도 되게 설계된 키*이고 보호는 RLS 가 함 |
| Supabase **service_role / secret 키** | ❌ 절대 금지 | 모든 보안정책을 무시하는 마스터키 |
| DB 비밀번호·대시보드 계정 | ❌ 절대 금지 | |
| 결과 보기 비밀번호(`RESULTS_KEY`) | ❌ 실제 운영 값은 올리지 말 것 | 아래 3번 참고 |
| 응답 데이터 | ❌ 올리지 않음 | DB 안에만 있음 |

`config.example.js` 는 값이 비어 있는 예시이고, 실제 값은 `config.js` 에만 넣습니다.

## 2. 익명(anon) 키로 할 수 있는 일 — 보안정책 요약

| 대상 | 읽기 | 추가 | 수정 | 삭제 |
|---|---|---|---|---|
| 회차 정의 `svy_surveys` | ✅ | ✅ | ✅ | ❌ |
| 응답 `svy_responses` | ✅ | ✅ | ❌ | ❌ |
| 브랜드 `svy_brands` | ✅ | ✅ | ✅ | ✅ |

삭제·응답 수정은 *정책*과 *권한 회수*(`revoke`) 두 겹으로 막혀 있어, 정책이 실수로 열려도 막힙니다. 확인 방법은 [`검증체크리스트.md`](검증체크리스트.md) 의 보안 항목.

## 3. 솔직한 한계 (꼭 읽을 것)

1. **결과 비밀번호는 화면을 가리는 용도일 뿐 DB 보호가 아닙니다.**
   브라우저에서 입력값을 `config.js` 의 값과 비교하는 방식이라, 페이지 소스를 열어 보면 값이 보입니다. 더 근본적으로, **anon 키로 응답 전체를 읽는 것은 비밀번호 없이도 가능**합니다(응답자 폰이 쓰는 키가 곧 그 키라서).
   → 응답에 **성별·연령대 외의 개인 식별 정보(이름·연락처 등)를 받지 마세요.** 이 시스템은 처음부터 개인이 아니라 그룹 단위 집계를 목표로 설계됐습니다.
2. **가짜 응답·회차 덮어쓰기가 가능합니다.** 응답 추가와 회차 수정이 익명에게 열려 있어(로그인 없이 편집기가 저장해야 하므로) 키를 아는 사람은 응답을 넣거나 회차 설정을 바꿀 수 있습니다. *지울 수는 없게* 막아 둔 것이라 손실은 막지만 오염은 막지 못합니다.
3. **비밀번호가 한 번이라도 공개 저장소에 올라갔다면** 지금 파일에서 지워도 git 기록에 남습니다. 그 경우 비밀번호를 **바꾸는 것**이 유일한 해결입니다(기록을 지우는 것은 공개 저장소에서 사실상 불가능).
4. 더 강하게 하려면: Supabase Auth 로 관리자 로그인을 도입하고 수정·삭제 권한을 로그인 사용자에게만 주는 방식(별도 작업). 이때 같은 프로젝트의 다른 앱과 세션이 섞이지 않게 앱 전용 `storageKey` 를 써야 합니다(아래 5번).

### 사진 저장소(`svy-photos`)도 같은 한계

- 익명 키로 **업로드는 가능하고 삭제는 불가능**하다(실제로 확인). 앱이 5MB·이미지 형식을 화면에서만 막으므로, 키를 아는 사람은 **아무 종류의 파일이나** 공개 저장소에 올릴 수 있다(2026-10-16 실제 확인: 텍스트 파일 업로드 성공).
- 막으려면 `supabase/storage.sql` 의 버킷 제한(5MB·이미지 MIME)을 Supabase SQL Editor 에서 실행한다. 올라간 파일 정리는 대시보드 Storage 화면에서만 가능.
- 사진 투표를 안 쓰는 설치에서는 이 저장소를 만들지 않는 것이 가장 안전하다.

## 4. 영구 삭제는 왜 웹에서 안 되나

누적 분석의 기준 데이터가 실수·장난으로 사라지는 것을 막기 위해서입니다. 웹 화면의 "숨기기"는 `archived=true` 로 바꾸는 *수정*이라 언제든 복원됩니다. 진짜 삭제는 Supabase 대시보드(SQL Editor)에서 [`maintenance.sql`](../supabase/maintenance.sql) 로만 합니다.

## 5. 같은 Supabase 프로젝트를 다른 앱과 같이 쓰면

다른 앱이 같은 프로젝트에 로그인 세션(`authenticated`)을 브라우저에 저장해 두면, supabase-js 가 익명 키 대신 그 로그인 토큰을 보내 보안정책이 응답을 0건으로 걸러내는 사고가 납니다(실제로 겪음). 이 앱은 세션 저장을 끄고 항상 익명으로 접속하도록 고정해 막아 두었지만, **가장 확실한 방법은 설문 전용 프로젝트를 쓰는 것**입니다.

## 6. 로컬 미리보기 서버(`serve.js`)

- `127.0.0.1` 에만 열려 **같은 네트워크의 다른 기기는 접속할 수 없고**, 저장소 폴더 바깥 파일(`../`, `..%2f` 등)은 403 으로 막습니다.
- 과거 버전은 모든 네트워크 주소에 열려 있고 폴더 이탈을 막지 않아, 저장소 바로 위 폴더의 파일을 내려받을 수 있었습니다. **저장소 바깥에 비밀번호·키가 든 문서를 두는 경우, 예전 버전의 `serve.js` 를 켜 두지 마세요.**
- 로컬에서 응답을 제출하면 `config.js` 가 가리키는 **실제 DB 에 저장**됩니다.
