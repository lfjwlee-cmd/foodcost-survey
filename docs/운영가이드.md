# 운영 가이드

설치는 [`README.md`](../README.md). 이 문서는 **설치 후 매 시식마다 하는 일**입니다.

## 1. 새 시식 회차 만들기

1. 응답 주소 끝에 `#admin` → 비밀번호 → **⚙️ 관리**
2. 브랜드가 없으면 **브랜드 관리 → + 브랜드 등록** (제품에 붙는 이름표·색. 시식 회차에만 쓰임)
3. **`+ 새 시식`** — *지금 활성인 회차(없으면 가장 최근 회차)를 복제*해서 시작합니다(제품·항목 이름까지 이어짐).
4. 회차 ID(자동 제안값 수정 가능)·제목·소개 문구 입력
5. **제품** 추가(`+ 제품`): **브랜드 칩**(여러 개 선택 가능) + 제품명 + 태그(예: `홀버전·1인 그릇`). 제품 이름은 서로 달라야 함(같으면 점수가 섞여 저장이 막힘)
   - **공통 메뉴**(여러 브랜드가 함께 출시): 브랜드 칩을 **둘 이상** 켠다(예: 과메기 → 삼대미역 + 어화락). 하나는 반드시 켜져 있어야 한다.
     결과 화면의 브랜드 필터·브랜드별 PDF 에서 **그 브랜드들 모두에** 포함돼 나오고, 랭킹·보고서에는 `삼대미역·어화락`으로 표시된다.
6. (선택) **평가 항목 이름** 수정 → 4번 항목 참고
7. **문항**(`+ 문항`, 제품과 무관한 회차 전체 질문) 추가: 선택 투표(버튼형/목록형)·사진 투표·자유 의견·추가 의견
   - 선택지는 **한 줄에 하나씩** 입력(쉼표로 나누면 `10,000원` 같은 값이 깨짐)
   - **구분 제목**(`문항 유형 → 구분 제목`): 질문이 아니라 화면에 제목 띠만 넣는다(번호 없음). 앞 문항 묶음과 뒤 문항 묶음을 시각적으로 나눌 때 쓴다.
     예) `반찬 3종 투표` 다음에 `전체 메뉴 공통 질문`을 넣으면 "제공된 음식의 온도"가 반찬에만 해당하는 것처럼 보이지 않는다.
     결과 화면·PDF·엑셀의 투표 집계도 이 제목별로 묶여 나온다.
   - **소속 브랜드**(구분 제목의 `소속 브랜드(선택)` 칩): 고르면 **그 제목 아래 투표**가 그 브랜드의 결과 화면 필터·브랜드별 PDF 에 들어간다
     (예: `반찬 3종 투표` → 어화락, `전골 그릇 투표` → 삼대미역). 비우면 공통이라 모든 브랜드 PDF 에 들어간다. 브랜드 PDF 에는 소속 구역 + 공통 구역의 투표가 나오고, 자유 의견은 전체/`투표·의견만`에만 나온다.
   - **결과 맨 위에 1위 강조**(선택·목록·사진 투표의 체크박스): 체크한 문항은 결과 화면 맨 위 💡 줄과 PDF 맨 위에 `📌 질문 → 1위 선택지 (득표수 · 비율)` 로 따로 나온다. 출시 조합 투표처럼 결론이 필요한 문항에 쓴다.
   - **3개 중 2개 고르기**처럼 복수선택이 필요하면 **조합을 선택지로** 만든다(`A + B` / `A + C` / `B + C`). 복수선택 문항은 없다.
   - 오른쪽 **미리보기**가 응답자 화면 그대로 실시간 반영됨
   - **순서**: 제품과 문항은 한 목록이고, 각 카드의 **▲▼** 로 순서를 바꾼다. 응답자는 위에서 아래 순서 그대로 진행한다
     (예: 삼대미역 제품들 → 그릇 투표 → 어화락 제품들). 오른쪽 미리보기의 번호(Q2, Q3…)로 확인.
   - 브랜드가 여러 개여도 **한 회차·한 QR** 로 진행 가능. 결과는 브랜드 필터·제품 상세로 나눠 본다. 다만 제품이 많으면 폼이 길어지니 **한 회차 4~5개 이하** 권장
     (제출은 맨 끝에 한 번이라 중간에 닫으면 응답이 사라짐)
8. **저장 & 응답 폼에 활성화**(바로 QR에 반영) 또는 **저장만**(비활성으로 저장)
9. 관리 → **응답 QR → QR 만들기** → 인쇄·게시

> 활성 회차는 **한 번에 1개**입니다. 새로 활성화하면 이전 회차는 자동으로 비활성이 되고 **응답은 그대로 보존**됩니다.

## 2. 투표(제품 없는) 회차

**`+ 새 투표`** — 제품 0개·응답자 정보 끔(완전 익명) 상태의 빈 틀에서 시작합니다. 제품을 하나 추가하면 시식 회차로 바뀝니다. 투표 회차는 평가 항목·랭킹·히트맵 없이 **문항별 득표·지지율·자유 의견**만 보여줍니다(동점이면 동점 항목을 모두 표시).

## 3. 평가 항목(8개)과 판정

제품마다 아래 8개를 각각 5~1점으로 평가합니다.

| 묶음 | 항목(기본 이름) |
|---|---|
| **맛 그룹** (3) | 첫맛 · 뒷맛 · 간의 적절성 |
| **관능 그룹** (5) | 향·풍미 · 색감 · 플레이팅 · 식감 · 제공량 |

- **맛** = 맛 그룹 3개의 평균, **관능** = 관능 그룹 5개의 평균
- **맛·관능 칸 수 바꾸기**: 기본은 맛 3 + 관능 5(총 8개 고정)지만 `관리 → 회차 편집 → 평가 항목 이름` 에서 바꿀 수 있다.
  - **회차 기본값**: 적용 대상이 `공통`일 때 `맛·관능 칸 수`(맛 2~6)를 고른다. 맨 위 항목부터 N개가 맛, 나머지가 관능이다(예: 맛 4 → 향·풍미 칸이 맛 쪽으로 넘어옴).
  - **제품 하나만**: 제품 카드 `✎ 항목 이름` → 같은 선택에서 `회차 기본` 또는 특정 칸 수를 고른다. 그 제품만 맛·관능 평균의 구성이 달라진다.
  - 4번째처럼 새로 맛 쪽으로 넘어온 칸은 이름·설명도 같이 바꿔 주면 좋다(예: 과메기 4번째 칸 `향·풍미` → `향`).
  - 제품마다 구성이 다르면 랭킹·PDF 에 `맛4·관능4` 표시가 붙고 판정 문구가 "맛(해당 항목 평균)"으로 바뀐다. **구성이 다른 제품끼리의 순위·점수 비교는 의미가 약하니** 메뉴별 판정으로 설명한다.
  - **응답이 1건이라도 있으면 잠긴다**(경계를 나중에 바꾸면 쌓인 평균이 소급해서 달라지므로).
- 평균을 **소수 첫째 자리로 반올림한 값**(화면에 보이는 값)으로 기준과 비교합니다(예: 4.1875 → 4.2 → 통과)

| 조건 | 판정 |
|---|---|
| 표본 3명 미만 | ⚪ 표본 부족 |
| 맛 ≥ 4.2 그리고 관능 ≥ 4.2 | 🟢 다음 단계 진행 |
| 맛만 미달 | 🟡 맛 보강 |
| 관능만 미달 | 🟠 관능 수정 |
| 둘 다 미달 | 🔴 맛·관능 보강 |

기준값은 `index.html` 의 `const TASTE_MIN=4.2, SENSORY_MIN=4.2, MIN_SAMPLE=3;` 한 줄입니다. 바꾸면 **저장된 과거 회차도 조회할 때 새 기준으로 다시 계산돼 보입니다**(판정은 저장하지 않고 열 때마다 계산).

> 표본이 적을 때 4.5처럼 높게 나오는 건 표본이 작아서 우연히 그럴 수 있습니다. 표본을 늘리면 평균이 *올라가는* 게 아니라 *더 정확해질* 뿐이며, 제품당 20~30명이면 오차범위가 대략 ±0.2 안으로 들어옵니다(점수 편차 σ≈0.5 가정).

## 4. 평가 항목 이름 바꾸기

튀김처럼 "첫맛·뒷맛"이 의미 없는 메뉴일 때, 같은 자리에 다른 이름을 붙입니다(예: 첫맛 → 바삭함).

- 위치: **관리 → 회차 편집 → 평가 항목 이름** (제품이 있는 시식 회차에만 보임)
- 바뀌는 것: **이름·설명만**. 항목 수(8)와 그룹(맛 3 / 관능 5)은 고정이라 *맛 평균은 이름과 무관하게* "맛 그룹 3개 평균"입니다.
- 제한: 이름 **8자 이내**(레이더·히트맵 라벨이 안 깨지는 한계), 설명 24자 이내, 이름 중복 불가, 비우면 기본 이름
- **응답이 1건이라도 있는 회차는 이름이 잠깁니다.** 이름을 바꾸면 앞선 응답자는 "첫맛", 뒷사람은 "바삭함"에 점수를 준 셈이 돼 한 열에 *서로 다른 질문의 답*이 섞이기 때문입니다. 바꾸려면 **새 회차**를 만드세요.
- **제품마다 다른 이름(권장)**: 메뉴 성격이 다르면(과메기 vs 미역전골) 제품 카드 오른쪽 위 **✎ 항목 이름** 을 눌러 그 제품만의 이름·설명을 정한다.
  바꾸지 않은 항목은 브랜드·공통 이름을 따라가고(●표시 = 바꾼 항목 있음), `브랜드·공통 이름과 같게` 로 되돌린다. 우선순위는 **제품별 → 브랜드별(제품이 한 브랜드일 때) → 공통**.
  공통 메뉴(브랜드 2개 이상)는 브랜드별 이름을 건너뛰고 공통(+제품별)만 쓴다. 이름 규칙은 같다(이름 8자·설명 24자 이내, 한 제품 안에서 중복 금지).
  **쉬운 말로 쓰는 요령**: 설명은 "~한가요?" 질문형으로, **5점이 "그렇다(좋다)"** 가 되게 쓴다. 맛 묶음 3칸·관능 묶음 5칸의 위치는 고정이라 내용만 바꾼다.
  예시(이름 / 설명):

  | 메뉴 | 맛 1 | 맛 2 | 맛 3 | 그 밖에 바꾸면 좋은 칸 |
  |---|---|---|---|---|
  | 과메기 | 고소함 / 기름의 고소한 맛이 좋은가요? | 비린내 없음 / 비린 맛 없이 깔끔한가요? | 느끼함 없음 / 기름져도 느끼하지 않나요? (대안: 신선함 / 신선하고 상태가 좋은가요?) | 식감→쫀득함 / 쫀득하고 촉촉한가요? |
  | 꼬막비빔밥 | 양념 맛 / 양념장 맛이 어울리나요? | 꼬막 맛 / 꼬막 맛과 신선함이 좋은가요? | 간·비빔 / 비볐을 때 간이 알맞은가요? | 식감→꼬막 식감 / 쫄깃하고 탱글한가요? |
  | 미역전골(얼큰) | 국물 맛 / 국물 첫맛이 좋은가요? | 개운함 / 먹고 난 뒤 개운한가요? | 간·칼칼함 / 간과 매운 정도가 알맞나요? | 식감→건더기 / 미역·건더기 식감이 좋나요? |
  | 반찬류 | 밥과 어울림 / 밥·메인과 잘 어울리나요? | 감칠맛 / 깊고 감칠맛이 있나요? | 간 / 짜지도 싱겁지도 않나요? | 식감 / 아삭·부드러움이 알맞나요? |

  ※ 과메기처럼 초장·쌈에 싸 먹는 메뉴는 먹는 사람마다 양념이 달라 "양념 간"이 모호하다 — 기호와 무관한 항목(느끼함·신선함)으로 바꾼다.
  ※ 맛 칸에 "식감"처럼 관능 칸 이름과 같은 말을 쓰면 한 제품 안에서 이름이 겹쳐 저장이 막히니 한쪽을 바꾼다.
- **브랜드 단위로 한꺼번에**: 한 브랜드의 모든 제품이 같은 이름을 쓰면 적용 대상에서 `○○ 제품들`을 고른다(제품이 둘 이상 브랜드에 걸쳐 있을 때만 보임).
- (참고) **브랜드마다 다른 이름**: 제품이 2개 이상의 브랜드에 걸쳐 있으면 항목 이름 영역 위에 **적용 대상** 선택이 생긴다. 기본은 `공통`(모든 브랜드),
  `어화락만 다르게`를 고르면 그 브랜드 제품에만 다른 이름·설명이 붙는다(예: 삼대미역은 첫맛, 어화락은 바삭함). 바꾸지 않은 항목은 공통 이름을 따라가고,
  `공통 이름과 같게` 버튼으로 그 브랜드의 변경을 모두 지운다. 이름이 달라도 **맛 그룹 3 / 관능 그룹 5 평균과 판정은 그대로**다.
  브랜드끼리 이름이 다르면 히트맵·엑셀 세그먼트 시트는 같은 이름 구성의 브랜드끼리 묶어 따로 보여 준다.
  ⚠️ 이름이 다른 브랜드의 점수를 한 순위표에서 비교하면 서로 다른 질문의 점수를 비교하는 셈이니 해석에 주의.
- **기본값으로 되돌리기** 버튼: `+ 새 시식`은 활성 회차를 복제하므로, 튀김 회차 다음에 탕 회차를 만들 때 이름이 딸려옵니다. 이때 누르세요.
- ⚠️ **이름이 다른 회차끼리는 합산·비교하지 마세요.** 같은 key 의 점수라도 의미가 다릅니다.

## 5. 결과 보기

- **회차 선택**(우측 상단): 활성이 아닌 과거 회차도 **그 회차 자신의 항목 이름·문항**으로 그려집니다.
- 필터: 브랜드·연령대·성별
- **KPI**: 응답자 수·대상 제품(전체 집계) / 맛·관능(**"제품 상세"에서 고른 제품 하나**의 값 — 다른 제품을 누르면 같이 바뀜)
- **선택·투표 집계**: 문항마다 선택지별 **득표수·비율**, 응답 인원·무응답 인원, 1위는 굵게(동점이면 ⚖ 동점 표시). 구분 제목별로 묶여 나온다.
- **제품 상세**(레이더·항목별 평균) → **제품 랭킹·판정** → 연령대×항목 히트맵 → 의견 → 문항별 집계
- 15초마다 자동 갱신
- **📄 보고서(PDF)**: 새 창이 열리면 인쇄 → PDF 로 저장. 브랜드가 2개 이상이면 창 오른쪽 위 **보고서 범위** 선택에서
  `전체`(전 브랜드 랭킹 + **브랜드마다 새 페이지**: 랭킹·제품별 항목 평균·평가자 구성 → 마지막에 투표·의견) / `○○만`(그 브랜드 페이지만) / `투표·의견만` 을 고른 뒤
  인쇄하면 된다. PDF 기본 파일명에 브랜드명이 붙는다(예: `…_어화락_결과보고서`). 팀별로 파일을 나눠 줄 때는 브랜드별로 한 번씩 저장.
- **📊 엑셀 저장**: `.xlsx` — 요약(제품 랭킹·판정) / 세그먼트(연령·성별별 평균) / 문항 집계 / 응답 원자료 / 자유 의견. 헤더는 실제 질문 문구, 점수는 숫자, 시각은 현지 시각. 라이브러리를 못 불러오면 CSV 로 자동 대체

## 6. 회차 정리

|---|---|
| 목록에서 치우기 | 관리 → 회차 목록 → **숨기기**(삭제 아님. 결과 조회·복원 가능) |

## 7. 알려진 한계

- **중복 응답을 막지 못함**: 익명 제출이라 한 사람이 여러 번 낼 수 있음. 표본을 늘려 신뢰도를 올리려는 시식에서는 현장 진행자가 1인 1회를 안내하세요.
- **복수선택(체크박스) 문항 없음**: 선택 문항은 전부 하나만 고르는 방식.
- **문항은 회차 전체 대상**: "제품별로 따로 묻는 문항"은 없음(제품별로는 8개 평가 항목만).
- **5축(구형) 회차와 8축 회차는 합산 불가**: 서로 다른 질문에 답한 데이터라 숫자가 왜곡됩니다. 같은 8축 구성 회차끼리만 합산 가능하며, **회차 합산 보기 화면은 아직 없음**.
- **한 화면에 최대 1000건**: Supabase 기본 조회 한도(보통 1000건) 때문에 응답이 그보다 많은 회차는 결과가 잘립니다.
- **활성 회차를 비워 두지 말 것**: 활성 회차가 없으면 응답 주소를 여는 순간 `questions.json` 샘플 회차가 자동 생성·활성화됩니다.
