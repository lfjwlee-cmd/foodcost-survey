# 운영 가이드

설치는 [`README.md`](../README.md). 이 문서는 **설치 후 매 시식마다 하는 일**입니다.

## 1. 새 시식 회차 만들기

1. 응답 주소 끝에 `#admin` → 비밀번호 → **⚙️ 관리**
2. 브랜드가 없으면 **브랜드 관리 → + 브랜드 등록** (제품에 붙는 이름표·색. 시식 회차에만 쓰임)
3. **`+ 새 시식`** — *지금 활성인 회차(없으면 가장 최근 회차)를 복제*해서 시작합니다(제품·항목 이름까지 이어짐).
4. 회차 ID(자동 제안값 수정 가능)·제목·소개 문구 입력
5. **제품** 추가(`+ 제품`): 브랜드 선택 + 제품명 + 태그(예: `홀버전·1인 그릇`). 제품 이름은 서로 달라야 함(같으면 점수가 섞여 저장이 막힘)
6. (선택) **평가 항목 이름** 수정 → 4번 항목 참고
7. **문항**(`+ 문항`, 제품과 무관한 회차 전체 질문) 추가: 선택 투표(버튼형/목록형)·사진 투표·자유 의견·추가 의견
   - 선택지는 **한 줄에 하나씩** 입력(쉼표로 나누면 `10,000원` 같은 값이 깨짐)
   - 오른쪽 **미리보기**가 응답자 화면 그대로 실시간 반영됨
   - **순서**: 제품과 문항은 한 목록이고, 각 카드의 **▲▼** 로 순서를 바꾼다. 응답자는 위에서 아래 순서 그대로 진행한다
     (예: 삼대미역 제품들 → 그릇 투표 → 어화락 제품들). 오른쪽 미리보기의 번호(Q2, Q3…)로 확인.
   - 브랜드가 여러 개여도 **한 회차·한 QR** 로 진행 가능. 결과는 브랜드 필터·제품 상세로 나눠 본다. 다만 제품이 많으면 폼이 길어지니 **한 회차 4~5개 이하** 권장
     (제출은 맨 끝에 한 번이라 중간에 닫으면 응답이 사라짐)
8. **저장 & 응답 폼에 활성화**(바로 QR에 반영) 또는 **저장만**(비활성으로 저장)
9. 관리 → **응답 QR → QR 만들기** → 인쇄·게시

> 활성 회차는 **한 번에 1개**입니다. 새로 활성화하면 이전 회차는 자동으로 비활성이 되고 **응답은 그대로 보존**됩니다.

## 2. 투표(제품 없는) 회차

**`+ 새 투표`** — 제품 0개·응답자 정보 끔(완전 익명) 상태의 빈 틀에서 시작합니다. 제품을 하나 추가하면 시식 회차로 바뀝니다. 투표 회차는 평가 항목·랭킹·히트맵 없이 **문항별 득표·지지율·자유 의견**만 보여줍니다(동점이면 동점 항목을 모두 표시).

## 3. 평가 항목(8개)과 판정

제품마다 아래 8개를 각각 5~1점으로 평가합니다.

| 묶음 | 항목(기본 이름) |
|---|---|
| **맛 그룹** (3) | 첫맛 · 뒷맛 · 간의 적절성 |
| **관능 그룹** (5) | 향·풍미 · 색감 · 플레이팅 · 식감 · 제공량 |

- **맛** = 맛 그룹 3개의 평균, **관능** = 관능 그룹 5개의 평균
- 평균을 **소수 첫째 자리로 반올림한 값**(화면에 보이는 값)으로 기준과 비교합니다(예: 4.1875 → 4.2 → 통과)

| 조건 | 판정 |
|---|---|
| 표본 3명 미만 | ⚪ 표본 부족 |
| 맛 ≥ 4.2 그리고 관능 ≥ 4.2 | 🟢 다음 단계 진행 |
| 맛만 미달 | 🟡 맛 보강 |
| 관능만 미달 | 🟠 관능 수정 |
| 둘 다 미달 | 🔴 맛·관능 보강 |

기준값은 `index.html` 의 `const TASTE_MIN=4.2, SENSORY_MIN=4.2, MIN_SAMPLE=3;` 한 줄입니다. 바꾸면 **저장된 과거 회차도 조회할 때 새 기준으로 다시 계산돼 보입니다**(판정은 저장하지 않고 열 때마다 계산).

> 표본이 적을 때 4.5처럼 높게 나오는 건 표본이 작아서 우연히 그럴 수 있습니다. 표본을 늘리면 평균이 *올라가는* 게 아니라 *더 정확해질* 뿐이며, 제품당 20~30명이면 오차범위가 대략 ±0.2 안으로 들어옵니다(점수 편차 σ≈0.5 가정).

## 4. 평가 항목 이름 바꾸기

튀김처럼 "첫맛·뒷맛"이 의미 없는 메뉴일 때, 같은 자리에 다른 이름을 붙입니다(예: 첫맛 → 바삭함).

- 위치: **관리 → 회차 편집 → 평가 항목 이름** (제품이 있는 시식 회차에만 보임)
- 바뀌는 것: **이름·설명만**. 항목 수(8)와 그룹(맛 3 / 관능 5)은 고정이라 *맛 평균은 이름과 무관하게* "맛 그룹 3개 평균"입니다.
- 제한: 이름 **8자 이내**(레이더·히트맵 라벨이 안 깨지는 한계), 설명 24자 이내, 이름 중복 불가, 비우면 기본 이름
- **응답이 1건이라도 있는 회차는 이름이 잠깁니다.** 이름을 바꾸면 앞선 응답자는 "첫맛", 뒷사람은 "바삭함"에 점수를 준 셈이 돼 한 열에 *서로 다른 질문의 답*이 섞이기 때문입니다. 바꾸려면 **새 회차**를 만드세요.
- **기본값으로 되돌리기** 버튼: `+ 새 시식`은 활성 회차를 복제하므로, 튀김 회차 다음에 탕 회차를 만들 때 이름이 딸려옵니다. 이때 누르세요.
- ⚠️ **이름이 다른 회차끼리는 합산·비교하지 마세요.** 같은 key 의 점수라도 의미가 다릅니다.

## 5. 결과 보기

- **회차 선택**(우측 상단): 활성이 아닌 과거 회차도 **그 회차 자신의 항목 이름·문항**으로 그려집니다.
- 필터: 브랜드·연령대·성별
- **KPI**: 응답자 수·대상 제품(전체 집계) / 맛·관능(**"제품 상세"에서 고른 제품 하나**의 값 — 다른 제품을 누르면 같이 바뀜)
- **제품 상세**(레이더·항목별 평균) → **제품 랭킹·판정** → 연령대×항목 히트맵 → 의견 → 문항별 집계
- 15초마다 자동 갱신
- **📄 보고서(PDF)**: 새 창이 열리면 인쇄 → PDF 로 저장
- **📊 엑셀 저장**: `.xlsx` — 요약(제품 랭킹·판정) / 세그먼트(연령·성별별 평균) / 문항 집계 / 응답 원자료 / 자유 의견. 헤더는 실제 질문 문구, 점수는 숫자, 시각은 현지 시각. 라이브러리를 못 불러오면 CSV 로 자동 대체

## 6. 회차 정리

| 하고 싶은 일 | 방법 |
|---|---|
| 목록에서 치우기 | 관리 → 회차 목록 → **숨기기**(삭제 아님. 결과 조회·복원 가능) |
| 되살리기 | 목록 하단 **보관한 회차 → 복원** |
| **영구 삭제**(되돌릴 수 없음) | 웹에서는 **불가능**하게 막아 둠. Supabase SQL Editor 에서 [`supabase/maintenance.sql`](../supabase/maintenance.sql) ④ 블록으로만 |
| 테스트 응답 정리 | 실제 제출 테스트는 **별도 테스트 회차**에서 하고, 끝나면 위 영구 삭제로 정리 |

## 7. 알려진 한계

- **중복 응답을 막지 못함**: 익명 제출이라 한 사람이 여러 번 낼 수 있음. 표본을 늘려 신뢰도를 올리려는 시식에서는 현장 진행자가 1인 1회를 안내하세요.
- **복수선택(체크박스) 문항 없음**: 선택 문항은 전부 하나만 고르는 방식.
- **문항은 회차 전체 대상**: "제품별로 따로 묻는 문항"은 없음(제품별로는 8개 평가 항목만).
- **5축(구형) 회차와 8축 회차는 합산 불가**: 서로 다른 질문에 답한 데이터라 숫자가 왜곡됩니다. 같은 8축 구성 회차끼리만 합산 가능하며, **회차 합산 보기 화면은 아직 없음**.
- **한 화면에 최대 1000건**: Supabase 기본 조회 한도(보통 1000건) 때문에 응답이 그보다 많은 회차는 결과가 잘립니다.
- **활성 회차를 비워 두지 말 것**: 활성 회차가 없으면 응답 주소를 여는 순간 `questions.json` 샘플 회차가 자동 생성·활성화됩니다.
